# 工具回显的 token 账本（2026-11-02）

目标：搞清**长会话的钱花在哪**，并把工具回显压到有界。所有数字都来自
`$DSH_HOME/sessions` 的真实语料（116 个会话 / 24,837 次工具调用），不是估算。

## 一、钱花在哪

| 项 | 字符 | 占比 |
|---|---:|---:|
| 工具回显 | 35,046,937 | **57.4%** |
| 对话正文（user + assistant） | 26,056,611 | 42.6% |

这里给的是全语料字符账，两个数不冲突，但引用时要写清口径。）

## 二、换个阈值能省多少

拿全部 24,837 次真实输出，按"超过阈值就换成 `阈值/4` 的预览"模拟：

| 阈值 | 回显字符 | 相对现状节省 | 预览保留 |
|---:|---:|---:|---:|
| 2,000 | 11,609,186 | **67.1%** | 500 |
| **4,000（当前）** | **18,015,616** | **48.9%** | 1,000 |
| 8,000 | 24,460,067 | 30.6% | 2,000 |
| 16,000 | 28,731,896 | 18.5% | 4,000 |
| 50,000（≈DSH 实际） | 35,212,489 | 0.1% | 12,500 |

**省 token 不是免费的**：阈值越低，模型越可能要再读一次工件（多一次调用）。
所以 4,000 是个折中，不是"越小越好"。要不要降到 2,000，得看"多出来的重读次数"——
这一步还没做，记在 `MAINTENANCE.md` 的下一步里。

## 三、发现的两个真 bug

### bug 1：spill 只换了 `Data`，模型看到的是 `Text`

`ProjectResult` 优先用 `Result.Text`。截断层只把 `res.Data` 换成预览，
`Text` 原样保留 —— **等于没截**。

实测证据（`TestSpillBoundsWhatModelSees`）：读一个 9,000 字符的文件，
阈值 4,000，改成旧逻辑后模型仍会看到 **9,361 字符**。

修法：`spill` 同时压 `Text` —— 留头 + 留尾 + 中间一行指针：

```
…（中间省略 18067 字符，全文在 tmp/spill-home2/artifacts/spill-0001-3910445575.json）…
```

留尾巴是因为日志、报错、命令输出的关键信息常在最后。

### bug 2：指针指向一个模型读不到的地方

外置目录原来是 `os.TempDir()/dshd-spill`，而 `Hint` 写着「用 read 读全文」。
但 `FS.Resolve` 只放行工作区 —— **那句 Hint 是假的**，模型照着做只会得到"越出工作区"。

修法：

- artifact 落到 `<home>/artifacts`（不是系统 temp）
- `FS` 加 `WithExtraReadRoot`：**只放读，不放写**，artifact 仍由宿主写
- `run` 的模块装配改用 `--home`（曾经错用 `defaultHome()`，导致 artifact 地点和
  FS 放行目录不一致）
