# 工具回显的 token 账本（2026-11-02）

目标：搞清**长会话的钱花在哪**，并把工具回显压到有界。所有数字都来自
`$DSH_HOME/sessions` 的真实语料（116 个会话 / 24,837 次工具调用），不是估算。

## 二、换个阈值能省多少

拿全部 24,837 次真实输出，按"超过阈值就换成 `阈值/4` 的预览"模拟：

| 阈值 | 回显字符 | 相对现状节省 | 预览保留 |
|---:|---:|---:|---:|
| 2,000 | 11,609,186 | **67.1%** | 500 |
| **4,000（当前）** | **18,015,616** | **48.9%** | 1,000 |
| 8,000 | 24,460,067 | 30.6% | 2,000 |
| 16,000 | 28,731,896 | 18.5% | 4,000 |
| 50,000（≈DSH 实际） | 35,212,489 | 0.1% | 12,500 |

**省 token 不是免费的**：阈值越低，模型越可能要再读一次工件（多一次调用）。
所以 4,000 是个折中，不是"越小越好"。要不要降到 2,000，得看"多出来的重读次数"——
这一步还没做，记在 `MAINTENANCE.md` 的下一步里。

## 三、发现的两个真 bug

### bug 1：spill 只换了 `Data`，模型看到的是 `Text`

`ProjectResult` 优先用 `Result.Text`。截断层只把 `res.Data` 换成预览，
`Text` 原样保留 —— **等于没截**。

实测证据（`TestSpillBoundsWhatModelSees`）：读一个 9,000 字符的文件，
阈值 4,000，改成旧逻辑后模型仍会看到 **9,361 字符**。

修法：`spill` 同时压 `Text` —— 留头 + 留尾 + 中间一行指针：

```
…（中间省略 18067 字符，全文在 tmp/spill-home2/artifacts/spill-0001-3910445575.json）…
```

留尾巴是因为日志、报错、命令输出的关键信息常在最后。

### bug 2：指针指向一个模型读不到的地方

外置目录原来是 `os.TempDir()/dshd-spill`，而 `Hint` 写着「用 read 读全文」。
但 `FS.Resolve` 只放行工作区 —— **那句 Hint 是假的**，模型照着做只会得到"越出工作区"。

修法：

- artifact 落到 `<home>/artifacts`（不是系统 temp）
- `FS` 加 `WithExtraReadRoot`：**只放读，不放写**，artifact 仍由宿主写
- `run` 的模块装配改用 `--home`（曾经错用 `defaultHome()`，导致 artifact 地点和
  FS 放行目录不一致）

## 六、阈值 A/B：调低阈值没有实测收益

问题：4,000 是不是该降到 2,000？（语料模拟说能再省 18 个点。）

做法：同一道题、同一份 17 KB 日志（NEEDLE 在第 386 行，靠近末尾），
四个阈值各跑 3 次，看输入 token / 工具调用次数 / 答对没有。

| max-chars | 输入 token（3 次） | 中位 | 工具调用 | 答对 |
|---:|---|---:|---|---:|
| 2,000 | 8,597 / 8,645 / 15,021 | **8,645** | 3 / 1 / 1 | 3/3 |
| 4,000 | 8,653 / 8,669 / 14,228 | **8,669** | 1 / 2 / 1 | 3/3 |
| 8,000 | 8,653 / 13,292 / 14,734 | 13,292 | 2 / 2 / 1 | 3/3 |
| 50,000 | 8,653 / 8,653 / 15,371 | **8,653** | 2 / 1 / 1 | 3/3 |

结论三条：

1. **四个阈值全部答对** —— 头 + 尾 + 指针的组合，让模型不需要全文。
2. **2,000 与 4,000 的中位几乎一样（8,645 vs 8,669）** —— 语料模拟里那 18 个点，
   在这道题上没有兑现，因为模型拿到 2,000 字符和 4,000 字符时**调用的次数一样**。
3. **真正的方差来自"模型这次决定调几次工具"**：调 3 次 ≈ 15,000 token，调 1 次 ≈ 8,600。
   一次工具调用的固定开销（5–6k）比阈值本身大一个数量级。

所以：**阈值不是杠杆，"少调一次工具"才是。**
4,000 保留（更小没有收益，更大只是把同样的钱花在一次调用里）。

要往这个方向继续，得看的是：**为什么模型会多调那一次** —— 是提示里没说清，
还是首屏信息不够。那是下一轮的事。

## 七、第二处浪费：工具结果被 JSON 转义了一遍

模型看到的 `bash` 结果原来是：

```
退出码 0，输出 10691 字节
{"bytes":11068,"preview":"{\"output\":\"第 1 行内容填充…\"}"}   ← 双层转义
（已截断：保留 999/11068 字节，全文在 …）
提示：结果已外置到 …                                              ← 和上一行说同一件事
```

三个毛病：

1. **双层转义**：`preview` 本身就是 JSON 串，外面又包了一层，引号和换行被转义两次。
2. **重复**：截断说明和提示都指向同一个地方。
3. **数字对不上**：摘要说"输出 10691 字节"，下一行说 `bytes: 11068`。

改法：

- `bash` 直接给 `Result.Text` = `[exit N] [cwd X]` + **原始输出**（不转义）
- 外置时 `Data` 只留 `{spilled, bytes, artifact}`，**不再放 preview**（正文由 Text 承担）
- 正文已经带指针时不再补一条同样意思的 Hint

现在同一个 10 KB 输出的样子：

```
[exit 0] [cwd /tmp/…]
第 1 行内容填充填充填充
…
（已截断：保留 4749/11068 字节，全文在 …/artifacts/spill-0001-….json）
```

**3,272 字符，全是能读的文本**（原来是 823 字符——但那 823 里有一半是转义和重复指针，
而且正文只有 1000 字符的 JSON 预览）。这次换来的不是"更少"，而是"同样的预算下信息更实"。

模型看到的成本上限仍然是 `max-chars`（默认 4000）。
