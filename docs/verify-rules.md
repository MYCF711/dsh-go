# 验证规矩（给派活的人看）

> 这里是**验收时反复吃过的亏**总结出来的规则。派活的任务书里应当直接引用对应条。
> 为什么不写进 AGENTS.md：那份文件正有一轮重写在途，不由我落；等它落地后加一行指针即可。

## 一、先验二进制版本，再验行为

**规矩**：任何真机探针跑之前，先跑 `scripts/bin-check.py`；旧了或两份副本分叉就**整轮中止**。

2026-11-03 的代价：h10 红了一次，被记成"宿主丢消息"，
实际是探针用着 **70 分钟前编译的二进制**（`tmp/serve-dir/dshd.exe` 17:35，源码 18:48）。
换同一个二进制立刻 6/6。

> 探针跑的是已经不存在的那版代码，结论却记在当前代码头上——**这比大多数 bug 都贵**，
> 因为它让人去改没坏的地方。

`bin-check` 已做成 `h-suite.py` 的第一条，红了会跳过后面全部真机探针。
它的反证（把二进制摸旧 → 必须红）在 `guard-selftest.py` 里。

## 二、"没有结论"不是"通过"

**规矩**：探针必须打出机器可读的汇总行（`合计 OK=x FAIL=y`）。没有汇总行——崩了、
超时、只把结果写进文件——**一律算失败**。

同理：`--only` 一条都没匹配到，不许报"全部通过"。

> 最坏的绿是"什么都没跑"的绿。

## 三、红的时候先问：是代码坏了，还是判据过期了

三种常见误判：

| 现象 | 常见真因 | 处置 |
|---|---|---|
| 探针超时 | 网关忙 / 等待窗口短于模型冷启动 | 给耐心，并让失败信息说清**等了多久、看到什么** |
| 断言红 | 探针按老契约写的 | 改断言到新形状，**别让宿主兼容两套真相** |
| 二进制旧 | 见第一条 | 重建 |

2026-11-03 一条 `6/7` 的前 6 项全过、只差"两边都收到 turn/done"——那是**探针的耐心**，
不是宿主串流。修探针时要求它同时说清**哪一边**没等到。

## 四、新增守卫必须能被反证

**规矩**：任何守卫（静态检查/脚本）都要在 `scripts/guard-selftest.py` 里加一条
"弄坏它、它必须红"。

> 跑不红的守卫等于没有守卫，而且它看起来正在检查——没有任何外部信号能反驳这一点。

实例：`flag-wired` 第一版把 `fs.String("dead", …)` 里的字符串 `"dead"` 当成了一次引用，
死开关永远是活的。自测第一次跑就抓出来了。

## 五、守卫各自能证明什么，写清楚

| 层 | 能证明 | 不能证明 |
|---|---|---|
| `help-guard` | 有同名开关、过期说法消失 | 说明本身**对不对** |
| `contract-evidence` | ✅ 点名的测试**存在** | 那个测试是否覆盖了这条需求 |
| `flag-wired` / `method-wired` | 被引用 / 被分发 | 引用分发到的地方**对不对** |
| 真机探针 | 端到端跑得过 | 界面怎么消费、负载下如何 |

**任何一层都不可以说"所以整链就对了"。**

## 六、并发：`-race` 能跑就必须跑

装 C 工具链之后 `bash scripts/race.sh` 全仓 39 包全 ok。它第一次跑就抓出三处
**测试夹具**的竞争（裸 slice / 裸 int 从 broker 的 goroutine 写、主 goroutine 读）。

夹具的竞争虽然不在产品代码里，但它会**淹没真正的竞争**——先清夹具。

成品不含工具链：`CGO_ENABLED=0` 构建，二进制里 `mingw` 字符串 0 处。
