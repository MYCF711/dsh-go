# 有意的放宽：一处一账

安全上有两种错法，第二种比第一种难发现得多：

1. **忘了收紧**——默认值写宽了，能靠 review 和门禁抓到；
2. **有意放宽，但没人知道**——写得对、有理由，可它悄悄扩大了权限面。

这份文档只记第 2 类：**每一处我们主动放宽的地方，放宽了什么、为什么、以及怎么让人看见**。

规矩：**有意的放宽必须配可见性**。看不见的放宽，与失误没有区别。

---

## 1. `dshd schedule run` 默认 `--policy=allow`

**放宽了什么**：定时任务到点执行的那一轮，写文件、跑命令都**不问人**。

**为什么**：定时任务是无人值守的。默认 `auto` 会让每个任务都在"没人点同意"上失败——
那等于这个功能完全不可用。

**怎么看见**：每次真跑都打一行

```
注意：这 1 轮用的是 --policy=allow（无人值守，写操作没有逐次询问）；要改成别的就带 --policy
```

**残留风险**：授权是在**登记时**给出的（模型可以自己 `schedule_create`），
执行时人不在场。也就是说，一个被允许 `schedule_create` 的会话，可以安排"两小时后无条件跑 bash"。

---

## 2. 子代理沿用主会话的审批记忆

**放宽了什么**：你在主会话里对某个工具选了"以后都允许"，**模型派出去的子代理**用同一个工具时不会再问。

**为什么**：同一个人、同一件事。每个子代理都重问一遍，等于把审批变成噪音，
而噪音会让人**闭着眼点同意**——那比不问更糟。

**怎么看见**：子代理的结果里写明

```
← subagent [ok] 子代理完成「回答 1+1」（3 步，25 字；沿用主会话审批记忆）
```

`spi.SubagentResult.BorrowedApprovals` 是给调用方看的字段；
把它写进 `Summary` 是刻意的——**Summary 是人看的那一行**。

**为什么以前看不见**：`dshd run` 的回显只有 `[ok]`，工具想说的一句话（Summary）
只进了模型上下文，人看不到。这一轮连这个一起修了：所有工具的 Summary 现在都会回显。

---

## 3. `dshd session compact --force`

**放宽了什么**：允许改写 `$DSH_HOME` 下的历史（`HistoryGuard` 默认拒绝）。

**为什么**：压缩本身是 append-only 的，但 CLI 上允许在托管目录里手动压一次，
用于修复被压坏的会话。

**怎么看见**：`--force` 是个显式参数，不带就不许；且日志会记下这次操作。

---

## 4. 模式的 `allow` 压过记忆里的拒绝

**放宽了什么**：`approvalDecision` 里，模式判定为 allow 时不问直接放行——**即使之前拒绝过**。

**为什么**：模式是用户显式选的（"这个会话就该只读"/"这个会话可以随便跑"），
它的意图比某一次的历史回答了更明确。

**怎么看见**：模式写进 `header.agentPreset`，`resume` 会采纳并在会话信息里显示。

---

## 不在本表的

- `.dshdignore` 跳过目录、`bash` 输出截断、`web_fetch` 512KB 上限——
  这些是**有界性**，不是权限；它们不扩大能做什么，只是限制一次能做多少。
