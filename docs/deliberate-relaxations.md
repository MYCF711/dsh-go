# 有意的放宽：一处一账

安全上有两种错法，第二种比第一种难发现得多：

1. **忘了收紧**——默认值写宽了，能靠 review 和门禁抓到；
2. **有意放宽，但没人知道**——写得对、有理由，可它悄悄扩大了权限面。

这份文档只记第 2 类：**每一处我们主动放宽的地方，放宽了什么、为什么、以及怎么让人看见**。

规矩：**有意的放宽必须配可见性**。看不见的放宽，与失误没有区别。

---

## 1. `dshd schedule run` 对**只读任务**不打扰

**放宽了什么**：定时任务到点执行时，只读工具（read / glob / grep / history_search …）
不问人直接跑。写类工具**默认拒绝**。

**为什么**：无人值守。每个任务都卡在"没人点同意"上，这个功能等于不存在；
但无差别放行写操作，又等于让模型能安排"两小时后无条件跑 bash"。

**怎么看见**：每条任务自带 `allow_writes`（默认 false），执行时打在屏幕上

```
跑 session-…b0cf  写文件 （只读：登记时没开 allow_writes）
  ← write [ERR] Error: 策略拒绝了 write
```

要开写操作，得在 `schedule_create` 里显式 `allow_writes: true`，而且会落盘。

**为什么不是"全允许"**：授权是在**登记时**给出的，提示词也是模型写的，
执行时人不在场。默认只读把"要不要给写权限"这个决定**拉回到有人在场的那一刻**。

**残留风险**：开了 `allow_writes` 的任务，到点后的一切写操作都不再问人。
这一点在 `schedule_create` 的参数说明里写死了。

### 顺带修的一个措辞

拒绝分两种，对模型的下一步要求不同：

- **人看了说不** → 可以重新征求同意、换个说法再来一次
- **策略不让人被问到**（`--policy deny` / 非终端 `auto`）→ 换问法没用，白跑一轮

以前两种都报「用户拒绝了 X」，模型会以为有人在，于是反复再试。现在分开：

```
← write [ERR] Error: 策略拒绝了 write     ← 换只读方式，或者别试了
```

**"谁来拒绝的" 是模型必须知道的信息，不是措辞问题。**

## 2. 子代理沿用主会话的审批记忆

**放宽了什么**：你在主会话里对某个工具选了"以后都允许"，**模型派出去的子代理**用同一个工具时不会再问。

**为什么**：同一个人、同一件事。每个子代理都重问一遍，等于把审批变成噪音，
而噪音会让人**闭着眼点同意**——那比不问更糟。

**怎么看见**：子代理的结果里写明

```
← subagent [ok] 子代理完成「回答 1+1」（3 步，25 字；沿用主会话审批记忆）
```

`spi.SubagentResult.BorrowedApprovals` 是给调用方看的字段；
把它写进 `Summary` 是刻意的——**Summary 是人看的那一行**。

**为什么以前看不见**：`dshd run` 的回显只有 `[ok]`，工具想说的一句话（Summary）
只进了模型上下文，人看不到。这一轮连这个一起修了：所有工具的 Summary 现在都会回显。

## 3. `dshd session compact --force`

**放宽了什么**：允许改写 `$DSH_HOME` 下的历史（`HistoryGuard` 默认拒绝）。

**为什么**：压缩本身是 append-only 的，但 CLI 上允许在托管目录里手动压一次，
用于修复被压坏的会话。

**怎么看见**：`--force` 是个显式参数，不带就不许；且日志会记下这次操作。

---

## 4. 模式的 `allow` 压过记忆里的拒绝

**放宽了什么**：`approvalDecision` 里，模式判定为 allow 时不问直接放行——**即使之前拒绝过**。

**为什么**：模式是用户显式选的（"这个会话就该只读"/"这个会话可以随便跑"），
它的意图比某一次的历史回答了更明确。

**怎么看见**：模式写进 `header.agentPreset`，`resume` 会采纳并在会话信息里显示。

## 5. `watch_ack` 的水位可以一次跳过一批编号

**放宽了什么**：`watch_ack` 把水位推到 `max(numbers)`。ack `[15]` 会让 4..14 永远不再被当成新活。

**为什么**：批量记帐是常态（一次处理了十个 issue），逐个 ack 纯粹是仪式。

**怎么看见**：跳过多少、跳过哪些，算出来写进 Summary，连续区间压成 `4-14`：

```
← watch_ack [ok] o/n 水位 3 → 15（跳过 11 个编号：4-14）
```

`Data` 里还有 `skipped` / `skipped_count`，Hint 直说"如果它们还没处理，现在就是最后的机会"。

**为什么这条特别危险**：写错一个文件还能改回来；水位推进错误是**静默的**——
它不会报错、不会重试、下次也不会再提。这类"跳过即消失"的副作用，
比任何一次写得过多都更难发现。

**现在会拦**：跳过**超过 3 个**编号时不带 `confirm_skip` 就拒绝。

```
← watch_ack [ok]  o/n 水位 0 → 3（跳过 2 个编号：1-2）        ← 跳 2 个，不打扰
← watch_ack [ERR] watch_ack: 跳过了 11 个编号，需要 confirm_skip  ← 跳 11 个，拦住
```

阈值定 3 的理由：正常批量记账常常中间空一两个号，不该打扰；
跳 4 个以上通常意味着"一次性把范围推到很后面"——那正是最容易把没处理的东西说成处理完的动作。

**拒绝是原子的**：被拦下的那次不写盘，水位停在原地。（第一版不是，
先 save 后校验，测试直接抓到 `拒绝后水位变成 15`。）

**残留**：靠阈值而不是靠事实。真要精确，得让 check 阶段把"见过哪些编号"落盘，
再用它校验——那要求 watcher 多存一份状态，还没做。

## 不在本表的

- `.dshdignore` 跳过目录、`bash` 输出截断、`web_fetch` 512KB 上限——
  这些是**有界性**，不是权限；它们不扩大能做什么，只是限制一次能做多少。
