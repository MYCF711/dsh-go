# `dshd doctor`：出问题时先跑它

目标不是"再跑一遍冒烟测试"，是**把已经坏掉的东西指出来**，并且每一项都给出
实测到的具体值 + 下一步该做什么。

## 用法

```bash
dshd doctor [--home X] [--base URL]
```

## 五项检查

| 项 | 怎么查 | 失败时的下一步 |
|---|---|---|
| **home 可写** | 在 home 里写一个探针文件再删掉 | 换目录 / 修权限 |
| **会话可读** | 抽样最多 200 份会话真解一遍 | 列出读不出来的那几份 |
| **写锁** | 找 `*.lock` | 给出锁文件路径，让人确认后删 |
| **模型网关** | `GET <base>/models`，5 秒超时 | 按状态码分开说（401 → key；5xx → 网关） |
| **模块装配** | 真读一遍 manifest | 指向 `dshd modules list` |

## 实测

正常：

```
dshd doctor · home=tmp/doc-ok

  ✓ home 可写        tmp/doc-ok（还不存在，第一次跑会自动建）
  ✓ 会话可读           还没有会话目录（第一次跑会建）
  ✓ 写锁             没有写锁
  ✓ 模型网关           连上了，63 个模型（group/deepseek-v4.1-flash1017）
  ✓ 模块装配           dsh.toml 读得通

一切正常。
```

home 是文件：

```
  ✗ home 可写        tmp/docfile 是一个文件
    → 换一个目录路径，或把那个文件挪走
```

网关不通：

```
  ✗ 模型网关           连不上 http://127.0.0.1:1/v1
    → 确认网关在跑（本机是 magpie，端口 3425）；或换个 --base
```

尾部半帧（**警告**，不是错误）：

```
  ✓ 会话可读           1 份可读，其中 1 份尾部有半帧（断电留下的）
    → 不用处理：前面的内容照常可用；`dshd session info --in <file>` 会提示截断位置
```

僵尸锁（**警告**）：

```
  ✓ 写锁             1 个锁文件
    → 如果确实没有别的 dshd 在写这些会话，删掉即可：<path>.lock
```

## 三个刻意的取舍

1. **会话抽样上限 200 份**。doctor 要在几秒内跑完，不是备份工具。
2. **锁只报警不报错**。Windows 上判断"那个 pid 还活着没"不可靠，
   与其猜错，不如把路径给人，让人来定。
3. **尾部半帧算 ✓ + 警告**。它能读、前面的内容可用，不该让人以为坏了。

## 退出码

| 情况 | 退出码 |
|---|---|
| 全绿 | 0 |
| 只有警告（!） | 0 |
| 有致命项（✗） | 1 |

可以直接用 `dshd doctor || echo 挂了` 接监控。

## 故障演练：四种真故障，doctor 指不指得出来

`scripts/doctor-drills.py` 把东西**真弄坏**，再看诊断输出。

```bash
python scripts/doctor-drills.py
```

| 演练 | 怎么造的 | doctor 的输出 | 结果 |
|---|---|---|---|
| **断电** | 跑到一半 `kill -9`，再砍掉尾部 6 字节 | `! 会话可读 1 份可读，其中 1 份尾部有半帧` | ✅ 指出来 |
| **僵尸锁** | 在真实会话旁写一个 `pid=999999` 的 `.lock` | `! 写锁 1 个锁文件` + 给出路径 | ✅ 指出来 |
| **网关 500** | 起一个返回 500 的 HTTP 桩 | `✗ 模型网关 http://…/models 返回 500` | ✅ 指出来 |
| **只读 home** | `icacls /deny <user>:(W)` | `✗ home 可写 写不进去: … Access is denied.` | ✅ 指出来（**但它没测到"存不下会话"**，见下） |
| **日志写不了** | 把 `logs` 做成一个文件 | `✗ 运行日志 … 是一个文件，不是目录` | ✅ 指出来 |

**五项全中。** 退出码也对：网关、home、日志是 `1`，两个警告是 `0`。

### 演练本身踩到两个坑（都记下来）

**一、判据不能只看 `✗`。** 尾部半帧和僵尸锁是**警告**——它们能跑，只是值得看一眼。
第一版脚本用 `✗` 当判据，把两项正确的输出判成"没指出来"。

**二、僵尸锁演练一开始什么都没造出来。** 那个 home 里根本没有会话，
`.lock` 无处可挂，doctor 报"没有写锁"是对的。后来先跑一次真实 turn 造出会话，
才把锁挂上去。

### 顺带修掉 doctor 自己的一个 bug

警告项（`OK && Warn`）原来渲染成 `✓`，但结尾那行说"上面 **!** 那行"——
**人对不上号**。现在警告优先：`Warn` 就先画 `!`，不管 OK 是不是 true。
`TestDoctorWarningIsVisibleInSummary` 钉住：有警告时不许打"一切正常"、警告行必须是 `!`。

## 运行日志：出事之后去哪儿查

`<home>/logs/<日期>.log`，一行一个 JSON。`run` 与 `acp` 都会写。

```
{"time":"2026-11-03T00:55:50Z","level":"INFO","msg":"会话开始",
 "session":"session-b953b7cc-…","path":"…/session.v4.jsonl.zstd",
 "cwd":"D:/…/DSH-GO","mode":"default","home":"tmp/log3"}
{"time":"2026-11-03T00:55:51Z","level":"WARN","msg":"工具调用失败",
 "tool":"read","ms":0,"ok":false,"args_bytes":33,"error":"/nonexistent.txt 不存在"}
```

三个刻意的选择：

1. **一行一个 JSON**——能 grep、能 `jq`、能直接贴给人看，不需要额外工具。
2. **失败也照打**：`run` 结束时会打一行 `日志: <path>`，**出错时也打**（`defer`）。
   以前出错只有一句 stderr，会话一关就没了。
3. **不替代 stderr**：原来的输出一个字都没变，日志是附加的。

### doctor 会指到那份日志

```
  ! 运行日志           dshd-2026-11-03.log 里有 1 条警告
    → 最后一条: 工具调用失败: /nonexistent.txt 不存在（完整内容见 …/dshd-2026-11-03.log）
```

数警告、带出最后一条错误原文、给文件路径——三步都不用你自己找。

### 一次失败现在长这样

```
$ dshd run --prompt "用 read 读 /nonexistent.txt"
  → read {"file_path": "/nonexistent.txt"}
  ← read [ERR]
…
日志: tmp/log3/logs/dshd-2026-11-03.log
```

翻日志能直接看到：**哪份会话**（id + 路径 + cwd + 模式）、**哪一步**（tool）、
**跑了多久**（ms）、**成没成**（ok）、**错误原文**。

钉住的测试：`TestPipelineLogsEveryToolCall`（每次调用都记，成败与错误原文都在）、
`TestDoctorPointsAtLastLogError`（doctor 指到文件并带出最后一条错误）、
`TestDoctorNoLogYet`（第一次跑没日志不算问题）。

## 记不了日志的时候会怎样（2026-11-03）

最坏的降级是**静默**：用户以为有记录，出事之后去翻，发现是空的。

修前的样子——`logs` 被一个文件占了，`run` 一声不吭照跑：

```
（什么都没有）
```

现在两处都说清楚：

```
$ dshd run …
警告: 这次没有事后可查的记录——tmp/nolog/logs 是一个文件，不是目录；删掉它（或换成别的 --home）
      宿主照常工作；想看日志就修好 tmp/nolog/logs 再跑
stats: tool_calls=0 input=4192 output=36        ← 活照样干完了
```

```
$ dshd doctor --home tmp/nolog
  ✗ 运行日志           tmp/nolog/logs 是一个文件，不是目录
    → 删掉它；在此之前 run/acp 都写不了日志，出事后没有东西可查
```

两条原则：

1. **不中断**：记不了日志不是不干活的理由。
2. **明说**：也不能假装记上了。

顺带修掉一处会误导人地方：doctor 原来把"日志目录读不了"也说成
**「还没有日志（跑一次就会写）」**——而它永远不会写。现在分开：
不存在 → 还没有；读不了/被占 → ✗。

## 纠正一处过度宣称：`icacls /deny (W)` 不等于"存不下东西"

这条演练之前写成"只读 home"，看完输出就以为覆盖了"会话存不下来"。
**实测发现它没覆盖。**

```
$ icacls <home> /deny <user>:(W)
$ bash -c "mkdir -p <home>/sub"      → rc=0      ← 建目录照样成功
$ dshd run --home <home> …            → 会话文件照样写出来了
$ python -c "open('<home>/p.txt','w')" → PermissionError   ← 只有这一条被挡
```

`(W)` 挡的是"在**这个目录里**新建文件"，挡不住"建子目录"，
也挡不住"往子目录里写文件"。所以那条演练真正的覆盖面是
**"doctor 的写探针会失败"**，不是"会话存不下来"。

要测后者，得换一个更直接的夹具：把 `sessions` 做成一个**文件**，
会话必然建不出来。

## 另一条顺序保证：存不下来就不要调模型

换夹具之后才看得到真正的问题：**会话都存不下来，还去调模型吗？**

`scripts/probe-no-persist.py`：`sessions` 做成文件 + 一个只计数、永远回 500 的网关桩。

```
$ python scripts/probe-no-persist.py
退出码: 1
最后一行: dshd: 建会话目录失败（…/sessions/…）: …；确认 --home 指向一个目录、且可写
网关被打了: 0 次

✓ 先确认会话能落盘，才去调模型——顺序是对的
```

ACP 那条路同样：

```
session/prompt: 失败: 建会话失败: 建会话目录失败（…）
网关被打了: 0 次
```

两条路都**先确认能落盘，再花钱**。这条以前只是"看起来是这样"，
现在有脚本能复现。
