## 1. 本轮结论（已定，不要再重新论证）

### 1.1 TUI 路线：**不重写，用官方 0.19 + tui2go**

- 官方 `@deepseek-harness-tui/dsh-tui@0.19.0` 功能完整（64 命令、8 面板、launchpad、side panel）。
- `dsh-tui2go` 已是**真实现**（6,660 行 TS：`backend.ts` 1,061 行、`transport.ts` 735 行、`events.ts` 656 行 + 17 个能力模块、30 个测试文件），不是脚手架。
- 自研 `cmd/dshtui`（9,779 行非测试 + 6,358 行测试，214 测试通过）**不再追功能**，降级为**诊断/应急客户端**：
  - `--dump-screen` = 无终端环境的视觉回归门
  - `--send` = 链路自检
  - 价值 = 官方 TUI 哪天不修了的退路。

### 1.2 GUI/TUI 融合：**分两层，只做会话层**

| 层 | 决定 |
|---|---|
| **界面融合**（GUI 内嵌 TUI） | ❌ **不做**。需 PTY + VT 模拟器，是独立项目，ROI 为负 |
| **会话融合**（同一 `dshd`、同一 session） | ✅ **必做**，成本 < 1 天 |

会话融合缺两件（宿主侧已支持，`Hub.Subscribe` 多订阅 + `journalEpoch/lastSeq` 补齐）：
1. `tui2go` 的 standalone 加 `--resume <sessionId>`（当前 `src/standalone/args.ts:69-75` 只有 `--base/--token`）
2. GUI 加"在终端打开"动作（`exec.Command` 拉起 TUI，传 session id + base + token）

**不要**把 GUI 的 `dsterminal` 当终端用——它自己写着「不是终端模拟器」（`plugins/dsterminal/terminal.go:3`）。

### 1.3 桌面端：**已经是 Go + Viva**，不需要换语言

- `../dsh-ui`：46,227 行 Go 非测试 + 260 个测试文件 + 25 个插件。
- `CGO_ENABLED=0` 是硬判据（`UIPLAN.md:23`），这条排除了 Gio/Fyne（都要 cgo）。
- Viva 依赖极简：`purego v0.11.1` + `go-toml v2.4.3`。
